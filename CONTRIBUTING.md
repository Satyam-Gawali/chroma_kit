# Contributing to ChromaKit

Thank you for your interest in contributing to ChromaKit! 🎨

Whether you're fixing a bug, improving documentation, adding tests, or proposing a new feature, your contributions are welcome.

## Getting Started

1. Fork the repository.

2. Clone the repository:

```bash
git clone https://github.com/Satyam-Gawali/chroma_kit.git
```

3. Create a new branch:

```bash
git checkout -b feature/your-feature-name
```

4. Install dependencies:

```bash
flutter pub get
```

5. Make your changes.

6. Run analysis and tests:

```bash
flutter analyze
flutter test
```

7. Commit your changes:

```bash
git commit -m "feat: add awesome feature"
```

8. Push and create a Pull Request.

---

## Contribution Guidelines

### Code Quality

- Follow Dart and Flutter best practices.
- Keep APIs simple and intuitive.
- Maintain backward compatibility whenever possible.
- Avoid introducing unnecessary dependencies.

### Documentation

When adding new functionality:

- Update README examples if needed.
- Add DartDoc comments for public APIs.
- Update CHANGELOG.md.

### Testing

New features should include appropriate unit tests.

Run:

```bash
flutter test
```

before submitting a Pull Request.

---

## Bug Reports

If you discover a bug, please open a GitHub Issue and include:

- Flutter version
- Package version
- Steps to reproduce
- Expected behavior
- Actual behavior

---

## Feature Requests

Feature suggestions are welcome.

Before opening a request:

- Check existing issues.
- Explain the use case.
- Describe the proposed API if applicable.

---

## Pull Request Checklist

Before submitting a Pull Request, make sure:

- [ ] Code is formatted using `dart format .`
- [ ] `flutter analyze` passes
- [ ] `flutter test` passes
- [ ] Documentation has been updated if required
- [ ] CHANGELOG.md has been updated (if applicable)
- [ ] New features include tests

---

## Code Style

Format code before committing:

```bash
dart format .
```

Analyze for issues:

```bash

```
